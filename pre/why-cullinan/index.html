    What Cullinan Is¶

    Cullinan is a Python web framework in which the application is declared, not assembled: you mark one entry method, declare services and controllers as ordinary decorated classes, and the framework resolves the object graph, the middleware order and the request path for you — over either a Tornado or an ASGI backend, without changing your code.

    That is the whole claim. Everything else on this page exists to make it checkable rather than aspirational.

    Why this page is mostly a table¶

    A framework's description is the easiest thing to inflate and the hardest thing to audit. "Fast", "lightweight", "production-ready" cost nothing to write and cannot be falsified, which is exactly why they are worth nothing to a reader deciding whether to depend on the project.

    So the claims here are the ones that can be checked by a machine, and each one names its evidence. The list below is extracted and verified by scripts/check_claims.py, which fails when a claim loses its evidence — a document that shrinks is more honest than a document that keeps claiming.

    What this page does not claim¶

    • Not "fastest". Numbers without a workload are decoration. The repository ships a benchmark you can run on your own machine (benchmarks/bench.py) rather than a headline figure that would not transfer.
    • Not "zero configuration". A framework that hides its configuration cannot be operated; this one shows you the knobs, in Deploying to Production.
    • Not "1.0". The line is pre-release. The API surface is frozen so that a dependency can be pinned without surprises, but behaviour may still change where a release note says so.
